Thermal Spoof
Off
⚠ Advanced feature — real safety risk
This overrides what the OS believes the device's temperature is while a game is running. That disables the phone's own overheat protection during exactly the situation — sustained load — where it matters most. Real damage (battery degradation, burns, fire in extreme cases) becomes possible without the normal safeguard catching it. Use only if you understand and accept this.

Thermal Spoof
Arms the override — actual spoofing only happens in-game
Mode
Lite
Advanced
Extreme
Lite still uses the previous thermal engine, but only on CPU/GPU/board zones: vendor thermal daemons are stopped and those zones report the spoof temperature. Battery, IIO, I2C, and hwmon stay real. Lower coverage, lower risk.
⚠ Sensor spoof — OS sees a fake temperature
Advanced uses the same bind-mount engine as the previous public release, across every temp bus (zones, battery, IIO, I2C, hwmon). Userspace reads the value you set below instead of the real sensor. That also means Android’s overheat protection is looking at a lie during sustained load. Real damage is possible. Use only if you accept this.
⚠ Extreme — full spoof, applied immediately
Same bind-mount coverage as Advanced (every temp bus), and it applies as soon as you arm it — not only when a game is open. Overheat protection is looking at a fake value the whole time it is on.
Spoof temperature
Value reported to the OS while spoofing is active. Previous release was fixed at 27°C.

Device Spoof
Off
⚠ Advanced feature — read before enabling
Reports a different device identity to the selected game so it unlocks FPS/refresh-rate tiers your hardware wasn't approved for. Games with server-side device checks (this includes most competitive titles) can flag this as tampering — accounts have been banned for spoofing in other apps, even when a given method felt undetected for a while. Use only if you accept that risk.
